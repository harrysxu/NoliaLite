# Nolia Lite MVP 测试计划

> 版本：0.1.0  
> 依据：`PRODUCT_REQUIREMENTS.md`、`UI_UX_SPEC.md`、`TECHNICAL_DESIGN.md`  
> 首发平台：macOS arm64

## 1. 目标与边界

测试目标是验证 Nolia Lite 作为“多窗口、每窗口单文档、所见即所得、本地优先”Markdown 编辑器的完整闭环，包括文件进入、编辑、渲染、安全保存、恢复、系统集成和发布包。

测试不得引入或默认接受以下非目标：工作区、文件树、标签页、窗口内多文档、分屏预览、账号、同步、AI、插件、数据库和 Web 发布能力。

结果状态：

- `PASS`：已执行且满足预期。
- `FAIL`：已执行且产品结果不满足预期。
- `BLOCKED`：环境不具备执行条件，不可视为通过或失败。
- `PARTIAL`：自动化部分通过，但仍有原生或性能步骤未执行。

## 2. 质量门禁

每个发布候选依次执行：

```sh
npm run verify
npm audit --omit=dev
npm run tauri:build
npm run test:release
```

`npm run verify` 必须包含 TypeScript 类型检查、全部 Vitest、全部 Rust 测试和前端生产构建。任一命令失败时不得进入发布签收。

## 4. 固定语料

Markdown corpus 至少包含：

- 中文、emoji、组合字符、长行、LF、CRLF、无末尾换行。
- Frontmatter、原始 HTML、未知语法、转义、嵌套列表和任务项。
- 行内/块公式、脚注引用/定义、安全 HTML。
- JavaScript 代码块、GFM 表格、相对图片、Mermaid 流程图和时序图别名。
- 固定页面语料使用 `docs/MARKDOWN_ELEMENT_SHOWCASE.md`，包含紧凑表、混合内容表、十列宽表及连续编辑说明。
- 2 MB、10,000 行性能语料。

语料的首要断言是 `open -> compose` 与原始文本逐字相等，不能用格式化后的“语义相等”替代。

## 6. 发布退出条件

- 自动化、Rust、依赖审计、生产构建和发布检查全部 `PASS`。
- 无 P0/P1 数据丢失、安全绕过或只读写入缺陷。
- N-01 至 N-18 全部实际执行且无 `BLOCKED`，才能声明完整 release acceptance 通过。
- 允许记录非阻断体积或 chunk 警告，但必须给出数值和后续阈值，不能隐藏。
