# Nolia Lite UI/UX 规格

> 版本：0.3  
> 状态：沉浸式编辑外壳修订  
> 关联需求：[PRODUCT_REQUIREMENTS.md](./PRODUCT_REQUIREMENTS.md)  
> 关联技术方案：[TECHNICAL_DESIGN.md](./TECHNICAL_DESIGN.md)  
> 首期平台：macOS  
> 体验参考：Typora 的即时排版；Nolia 的复杂 Markdown 渲染与操作

## 1. 文档目的

本文定义 Nolia Lite MVP 的信息架构、窗口布局、编辑交互、文件流程、状态反馈、视觉系统、响应式规则和可访问性标准。

设计目标不是复制 Typora 的所有界面，也不是给 Nolia 删除几个模块。Nolia Lite 应表现为一个独立、安静、可靠的单文档工具：打开即阅读，点击即编辑，离开前明确处理内容。

## 2. 体验目标

### 2.1 用户应感受到

- 文档本身始终是窗口里的第一视觉主体。
- 打开 Markdown 后不需要理解“模式”，直接阅读和编辑。
- Markdown 输入习惯仍然有效，但大部分时间不需要面对完整源码。
- 保存状态始终可判断，失败和冲突不会被隐藏。
- 文件属于用户，应用不会建立工作区、导入副本或改变相对路径。
- 界面与 macOS 一致，不像浏览器后台或知识管理系统。

### 2.2 用户不应遇到

- 工作区选择、项目初始化或文件夹授权步骤。
- 标签页、文件树、右侧属性栏、底部状态栏。
- 源码/预览/分屏模式切换。
- 首次启动教程、功能轮播或大面积欢迎页。
- AI、插件、同步、登录、升级推销和联网提示。
- 因自动保存频繁闪烁、弹 toast 或打断输入。
- 无解释的内容重排、语法丢失或外部文件覆盖。

## 3. 设计原则

### 3.1 文档优先

正文占据绝大部分视口。窗口控件使用低对比度中性色，只有当前操作、错误或冲突使用强调色。

### 3.2 单一模式

界面中不出现“编辑”“预览”“源码”等模式名。局部源码只用于 Frontmatter、未知语法、链接等需要精确表达的元素，不构成全局模式。

### 3.3 渐进显现

格式工具、表格控制、链接字段、图表查看器和局部源码只在相关选择或焦点出现。关闭焦点后恢复排版视图。

### 3.4 安静但不隐瞒

正常保存使用稳定的标题栏状态，不弹成功提示。冲突、失败、只读和文件删除必须明确显示，并给出不会丢内容的下一步。

### 3.5 原生预期

系统文件对话框、macOS 菜单、标准快捷键、焦点行为和关闭确认遵循平台习惯。不要用自定义网页控件仿造文件选择器。

### 3.6 功能克制

一个控件只有在直接服务当前文档时才出现。没有功能面板、设置中心或“以后可能用到”的入口。

## 4. 信息架构

MVP 只有两个主界面状态：

```text
Application
├── Empty State
│   ├── New document
│   ├── Open document
│   ├── Recent files (0-5)
│   └── Recoverable untitled draft (when present)
└── Document State
    ├── Title bar
    ├── Transient status band (when needed)
    ├── WYSIWYG canvas
    ├── Find bar (transient)
    ├── Selection / element controls (transient)
    └── Decision dialog (blocking states only)
```

不设置路由、页面导航、侧栏层级或“返回首页”按钮。新建和打开直接替换当前会话，并先经过安全切换流程。

## 5. 窗口规格

### 5.1 基础尺寸

| 属性 | 规格 |
|---|---|
| 默认窗口 | `940 x 720px` |
| 最小窗口 | `560 x 480px` |
| 最大窗口 | 不限制，支持 macOS Zoom |
| macOS 标题栏/拖动区 | `38px` 高 |
| Windows/Linux 标题栏 | 系统原生，不叠加 WebView 标题区 |
| 正文默认最大宽度 | `880px` |
| 正文水平留白 | 常规每侧至少 `40px`，紧凑每侧 `16px` |
| 正文顶部留白 | `28-44px`，紧凑 `24px` |
| 正文底部留白 | `max(96px, 18vh)`，紧凑 `72px` |

窗口尺寸存于本机偏好 JSON，只记录宽、高和位置，不记录文档会话。窗口越界时回落到当前显示器可见区域。

### 5.2 标题栏

macOS 使用原生 traffic lights 与 overlay 标题栏。自定义区域只承担拖动和文件名/状态展示，必须保留 traffic lights 安全区。Windows 和 Linux 使用完整原生标题栏，WebView 不再绘制第二层标题区。

```text
+------------------------------------------------------------------+
| [traffic lights]                 document-name.md                  |
+------------------------------------------------------------------+
```

布局使用对称的稳定三列：

- 左侧：`minmax(84px, 1fr)`，包含 traffic lights 安全区，不放业务控件。
- 中间：内容宽度列，文件名和保存状态相对整个窗口居中。
- 右侧：`minmax(84px, 1fr)`，只用于平衡居中，不放业务控件。

紧凑窗口允许左右列同步缩小，但必须保持等宽；不能通过压缩左侧 traffic lights 安全区换取空间。

标题过长时单行省略，完整名称和路径通过悬停 tooltip 展示。标题栏不显示父文件夹面包屑。

文档模式不显示新建、打开、保存、导出或更多按钮。新建、打开、保存、另存为、导出和查找通过原生应用菜单及标准快捷键完成；空状态仍保留新建和打开两个鼠标入口。复杂块与格式操作继续按选区、焦点或右键渐进显现。

窗口级关闭、最小化、最大化控件始终使用操作系统原生实现：macOS 位于左侧 traffic lights 区域；Windows 位于右上角原生标题栏；Linux 服从桌面环境和窗口管理器设置，可能位于任一侧。Nolia Lite 不复制、模拟或重排系统窗口控件。

### 5.3 保存状态

文件名右侧显示一个不带胶囊背景的状态：

| 状态 | 文案 | 图标/颜色 | 行为 |
|---|---|---|---|
| 新建空白 | 尚未保存 | 空心圆；文案供辅助技术读取 | `Command+S` 打开保存对话框 |
| clean | 已保存 | 不显示标记；文案供辅助技术读取 | 无动画 |
| dirty | 未保存 | 实心小圆；文案供辅助技术读取 | 等待自动保存 |
| saving | 正在保存 | 小型旋转进度；文案供辅助技术读取 | 不阻止输入 |
| conflict | 保存冲突 | TriangleAlert，警示色 | 点击打开冲突对话框 |
| error | 保存失败 | CircleAlert，危险色 | 点击查看操作选项 |
| readonly | 只读 | Lock，中性 | 点击说明原因 |
| missing | 原文件不存在 | FileWarning，警示色 | 点击另存为 |

正常状态不以常驻文字占用标题区；异常、冲突、只读和文件缺失显示 `11px` 短文案并同时在状态带给出完整操作。所有状态保留 `role=status` 文本，Windows/Linux 还会同步到原生窗口标题，不能只靠颜色表达。

## 6. 空状态

### 6.1 布局

空状态不是营销欢迎页。内容区域最大宽度 `440px`，在视口中视觉居中略偏上。

```text
+------------------------------------------------------+
| title bar                                            |
|                                                      |
|                     Nolia Lite                       |
|                                                      |
|              [New document] [Open file]              |
|                                                      |
|              最近文件                                |
|              README.md                 yesterday     |
|              Notes.markdown            Jul 24        |
|                                                      |
+------------------------------------------------------+
```

允许显示：

- 产品名 `Nolia Lite`，`20px`，不是 hero 标题。
- “新建文档”和“打开文件”两个明确命令按钮，带图标和文字。
- 最近文件标题和最多 5 条无卡片列表。
- 存在未命名恢复草稿时显示一条“未保存的草稿”，与最近文件同级。

不显示：

- 产品特性、使用教程、快捷键说明。
- 插画、渐变、装饰图形、版本动态。
- 文件夹扫描结果或推荐内容。

### 6.2 最近文件行

- 行高 `44px`，无外层卡片；行间使用细分隔线。
- 左侧显示 FileText 图标和文件名，右侧显示简短时间。
- 路径只在 tooltip 中出现，不在主界面占两行。
- 单击直接打开。
- 文件不存在时降低文字对比度并显示 FileWarning；单击后提供“从最近文件中移除”。
- 键盘上下键移动，Enter 打开，Delete 只从最近列表移除，不删除磁盘文件。

## 7. 文档编辑界面

### 7.1 画布布局

编辑区域不是卡片。页面背景与正文连续，只通过宽度和留白形成阅读画布。

```text
+------------------------------------------------------------------+
| title bar                                                        |
+------------------------------------------------------------------+
| optional transient status band                                  |
+------------------------------------------------------------------+
|                                                                  |
|            # Rendered heading                                    |
|                                                                  |
|            Body text remains the visual focus.                   |
|            The caret edits the rendered document directly.       |
|                                                                  |
|            > Quote                                               |
|                                                                  |
|                                                                  |
+------------------------------------------------------------------+
```

- 正文宽度：`min(880px, calc(100% - 80px))`。
- 小于 `720px` 时：`calc(100% - 32px)`。
- 编辑器根节点具有稳定最小高度，点击文档末尾空白可把光标放到最后一段，但不会因 placeholder 改变布局。
- 页面不显示纸张阴影、边框或分页效果。
- 滚动条使用系统行为，不自定义常驻轨道。

### 7.2 编辑焦点

- 打开文档后，默认保持阅读位置；不强制把光标放入正文。
- 新建文档后，光标直接位于第一段。
- 点击排版内容直接进入编辑。
- Escape 关闭临时控件并回到编辑器，不退出文档。
- 选区和光标不能因自动保存、状态变化或图片加载跳动。

### 7.3 Placeholder

空文档不显示功能说明或引导文案。编辑器保留一个稳定的空段落和可见光标，点击正文空白即可聚焦；空状态不能因焦点或输入发生布局位移。

## 8. 排版与 Markdown 交互

### 8.1 基础行为

- 用户始终在渲染后的标题、段落、列表、引用、代码、链接、图片、表格、公式、脚注、HTML 和图表上编辑。
- 输入块级 Markdown 前缀并按空格或 Enter 后，当前块立即转换。
- 转换不能吞掉用户文本；撤销一次应恢复转换前源码输入。
- 格式变化只影响当前选区或后续输入，不显示完整 Markdown 源文件。

### 8.2 块级输入

| 输入 | 触发 | 结果 |
|---|---|---|
| `# ` 至 `###### ` | 空格 | 1-6 级标题 |
| `> ` | 空格 | 引用块 |
| `- `、`* `、`+ ` | 空格 | 无序列表 |
| `1. ` | 空格 | 有序列表 |
| `- [ ] ` / `- [x] ` | 空格 | 任务列表 |
| 三个反引号 | Enter | 代码块 |
| 文档首个空块中的 `---` | Enter | 创建 Frontmatter 局部源码区域，光标进入定界符之间 |
| 其他位置的 `---`、`***`、`___` | Enter | 分隔线 |

转换后不常驻显示输入前缀。普通点击当前标题后，只把该标题替换为包含对应 `#` 数量的局部 Markdown 输入；可直接增删 `#` 修改标题等级，提交或失焦后恢复排版视图。局部输入不切换整篇文档模式，也不改变其他块的布局。

### 8.3 行内输入

- `**text**`、`*text*`、`~~text~~`、反引号包裹文本在完成闭合标记后转换。
- 转换后的标记通常隐藏；普通点击粗体、斜体、删除线或行内代码后，只把命中的连续格式范围替换为包含包裹字符的局部 Markdown 输入，可直接修改 `**`、`*`、`~~` 和反引号。
- 局部源码按 Enter 或失焦提交，按 Escape 取消；提交后光标回到正文并恢复排版视图。
- 行内代码使用等宽字体和轻微背景，不使用高饱和色。
- 软换行遵循 Markdown 语义，不人为显示换行符。

### 8.4 选区浮动工具条

非空文本选区稳定后显示：

```text
[Bold] [Italic] [Strike] [Code] | [Link]
```

- 高度 `36px`，圆角 `6px`，单层浮层，不嵌套卡片。
- 图标按钮命中区域 `28 x 28px`。
- 默认位于选区上方，空间不足时翻转到下方。
- 不遮挡选区和当前输入行。
- 拖动选择、IME composition 和触摸板滚动时暂不显示。
- 点击格式后保留合理选区；Escape 或点击外部关闭。
- 按钮具有 tooltip、ARIA label 和按下状态。

不加入标题、引用、列表、颜色、对齐、AI 或更多格式菜单。

### 8.5 标题

- H1-H6 采用递减字号和稳定上下间距。
- 不用巨大 hero 字体；H1 最大 `32px`。
- 标题内支持基础行内格式和链接。
- Enter 在标题末尾创建普通段落；空标题按 Backspace 降级为段落。

### 8.6 列表与任务

- 列表标记与正文对齐，不出现额外卡片背景。
- Enter 创建同级项；空项 Enter 退出列表。
- Tab/Shift+Tab 调整层级，前提是不会破坏当前选择。
- 任务复选框是可操作原生语义控件，点击形成一次可撤销编辑。
- 复选框命中区域至少 `24 x 24px`，视觉尺寸约 `16px`。

### 8.7 引用与分隔线

- 引用使用 `3px` 左边线和轻微缩进，不使用整块彩色卡片。
- 分隔线为单条中性细线，上下留白稳定。
- 不支持 callout、admonition 或折叠引用。

### 8.8 代码

- 行内代码：等宽字体、`3px` 水平内边距、`3px` 圆角。
- 代码块：已知语言使用本地语法高亮，未知语言回退纯文本；等宽 `14px`，保留水平滚动。
- 代码块不是嵌套卡片；使用轻微背景和左侧/顶部边界区分。
- 语言标识只在已有语言或代码块聚焦时显示为小型文字按钮。
- 三个反引号不是常驻可见；精确围栏由保存层处理。
- Tab 在代码块中插入缩进，不移动页面焦点；`Command+]` 不增加新功能。

### 8.9 链接

- 链接使用系统强调色和下划线，保证与普通文本可区分。
- 普通点击已有链接时，渲染链接在原位置切换为完整 `[文本](地址)` Markdown 输入；正文宽度、上下文位置和滚动位置保持稳定，不出现浮层。
- 原位输入使用正文级字号的等宽字体、透明背景和无边框样式；只隐藏当前链接，其他正文继续保持渲染状态。
- Enter 或失焦提交，Escape 取消并恢复原渲染；不合法的链接 Markdown 不改写文档。
- 相对链接地址在原位源码或命令表单中显示并保存原字符串，不自动改写为绝对路径或规范化 URL；label 内的粗体等行内格式继续保留。
- `Command/Ctrl+Click` 把链接交给系统默认浏览器，普通点击不导航。
- 远程地址不会被应用预取、检查或生成预览。
- `Command/Ctrl+K` 或选区工具条用于创建/命令式编辑链接，显示与 Nolia 一致的“文本 + 链接”两字段表单以及“取消/确定”动作；该表单不用于普通点击已有链接。

### 8.10 图片

- 本地相对路径图片按原比例显示，最大宽度 `100%`，不得撑破画布。
- 图片加载前使用固定 aspect-ratio 占位，加载后避免正文突然大幅位移。
- 点击图片显示细焦点框和紧凑控件，可编辑 alt 与相对路径。
- 不显示绝对路径，不自动复制、不压缩、不上传图片。
- 远程图片不加载，显示等尺寸受控占位，包含 ImageOff 图标、alt 和原地址的截断文本。
- 本地图片缺失时显示 ImageOff 和相对路径；文档仍可编辑和保存。
- MVP 不提供缩放手柄、裁切、对齐、图注和资源管理器。

### 8.11 表格

- 表格使用内容优先的宽度；短表不强制平均拉满正文，超出画布时只在表格自身区域水平滚动，不扩大页面。
- 单元格最小宽度 `88px`，内边距 `6px 9px`；单元格段落不继承正文段落底部间距。
- 表头仅通过字重和中性背景区分。
- Tab 移到下一个单元格，Shift+Tab 移到上一个；最后一格 Tab 新增一行。
- 选中单元格时，在表格边缘显示单层小工具条：更多操作、左/中/右对齐和删除整表。
- “更多”菜单提供左右新增列、上下新增行、删除当前行列、表头行/列表切换、尺寸选择和 Markdown 源码编辑。
- 右键单元格打开同一操作菜单，并把活动单元格恢复为命令目标。
- 插入表格使用 `8 x 10` 网格选择器；尺寸调整使用 `10 x 10` 网格并标识当前大小。
- 源码 popover 编辑整张 GFM 表格；无效内容保留输入和错误，不替换当前表格。
- 不提供合并单元格、排序、筛选、电子表格公式和颜色。

### 8.12 Mermaid 图表

- 流程图、时序图和其他 Nolia 支持的 Mermaid 围栏直接显示为 SVG，不显示代码块。
- 普通点击图表进入该块完整 Markdown 围栏的局部源码编辑；Escape 退出并恢复渲染。
- `Command+Click`（Windows/Linux 为 `Ctrl+Click`）打开图表查看器，不进入源码。
- 查看器工具条依次为缩小、比例、重置、放大、PNG 下载、编辑源码和关闭。
- 初始比例 `125%`，每次调整 `25%`，允许 `50%-300%`；`+`/`-` 缩放，F2/E/修饰键 Enter 返回源码。
- 无效 Mermaid 在原块显示克制的错误状态；源码仍可进入、复制、修复和保存。
- 图表复制得到 Markdown 围栏，不得到 SVG 或位图。

### 8.13 公式、脚注与安全 HTML

- 行内公式保持行内基线，块公式居中排版；点击进入带定界符的局部源码。
- 脚注引用可跳转到当前文档定义；引用和定义可局部编辑 Markdown。
- 安全 HTML 按 Nolia 的清洗规则渲染；不安全内容显示 protected source，绝不执行脚本或远程嵌入。
- 这些局部编辑器使用与 Mermaid 相同的焦点规则：普通点击进入、Escape 退出、错误不丢输入。

### 8.14 Frontmatter

- 文档开头 Frontmatter 显示为等宽局部源码区域。
- 默认完整显示，不转换成属性表单。
- 未聚焦时视觉低调；聚焦后显示边界和原始 `---`。
- 编辑只发生在该区域，不切换整篇源码。
- 不显示 YAML 自动完成、类型提示或格式化命令。
- MVP 不解析或校验 YAML；保存层按用户输入原样处理该局部区域。

### 8.15 未支持语法与不安全 HTML

- 显示为 `protected source` 局部源码块，使用 Code2/Shield 图标和简短类型标签。
- 不安全 HTML 永远不渲染，不显示脚本、iframe 或嵌入结果。
- 未聚焦时源码可选择和复制；进入局部编辑后可修改原始文本。
- 局部块不提供“启用渲染”或插件安装入口。
- 标签仅说明当前状态，例如“未支持的 Markdown”或“原始 HTML”，不宣传功能。
- 该块的存在不阻止编辑文档其他部分。

## 9. 查找

`Command+F` 在标题栏下方、编辑区右上方显示紧凑查找条：

```text
[ search field             ] [3/8] [up] [down] [close]
```

- 宽度 `320px`，窄窗口为 `calc(100% - 24px)`。
- 不改变正文宽度；作为浮层覆盖顶部空白，但不能遮挡当前匹配，必要时滚动。
- 打开时自动选择原搜索词；为空时不显示 `0/0`。
- Enter 下一项，Shift+Enter 上一项，Escape 关闭并恢复编辑器焦点。
- 当前匹配与其他匹配使用两级对比，浅色/深色均可区分。
- 不提供替换、正则、大小写开关、搜索历史或跨文件入口。

## 10. 文件流程

### 10.1 启动

```text
启动
  -> 有 Finder 打开路径：读取并进入文档
  -> 无路径：显示空状态和最近文件
  -> 有未命名恢复草稿：在空状态最近列表上方显示恢复项
```

启动不自动重开上次文档，不扫描文件夹，不创建空文档。

### 10.2 新建

- 空状态点击“新建文档”后立即进入空编辑器并聚焦。
- 已有文档时从菜单或快捷键新建独立窗口，不替换当前窗口内容。
- 新建文档标题为“未命名”，状态为“尚未保存”。

### 10.3 打开

- 使用 macOS 系统文件对话框，只允许 `.md` / `.markdown`。
- 文件对话框允许多选；空窗口承载第一份文件，其余文件分别打开独立窗口。
- 读取期间标题显示文件名和小型进度，不用整页骨架动画。
- 打开失败保留当前文档；空状态下失败则继续留在空状态。
- 已有文档的窗口打开文件时不替换当前内容，目标文件进入新窗口。

### 10.4 保存

- 已有可写路径：编辑后状态变为“未保存”，约 800ms 后变为“正在保存”，成功后为“已保存”。
- 正常成功不显示 toast、横幅或声音。
- `Command+S` 立即保存。
- 新建文档 `Command+S` 打开系统保存对话框。
- 取消保存对话框后仍保留内存内容与恢复草稿，状态保持“尚未保存”。

### 10.5 另存为

- 从标题栏更多菜单、保存失败状态或冲突对话框进入。
- 使用系统保存对话框，默认文件名来自当前文档标题。
- 成功后当前会话切换到新路径，标题、最近文件、监听和保存基线同步更新。
- 原文件不再是当前会话对象，不形成第二个标签页。

### 10.6 拖放打开

- 文件进入窗口时，只显示轻微全窗描边和文件名，不显示教程式大文案。
- 放下后先验证类型；空窗口复用自身，已有文档时创建新窗口，多文件逐一打开。
- 无效文件使用短暂状态带提示，不清空当前文档。
- 拖放选中文本或编辑器内部内容时不能触发文件打开。

### 10.7 安全切换与关闭

| 当前状态 | 新建/打开/关闭行为 |
|---|---|
| clean | 直接继续 |
| dirty + 已有路径 | 先立即保存；成功后继续 |
| dirty + 未命名 | 保存 / 丢弃 / 取消 |
| saving | 等待本次保存结果；保持界面可响应 |
| conflict | 打开冲突决策，不继续切换 |
| error | 重试 / 另存为 / 保留草稿并退出 / 取消 |
| readonly 未编辑 | 直接继续 |
| missing | 另存为 / 保留草稿并退出 / 取消 |

“丢弃”是破坏性命令，必须明确写出，不使用模糊的“否”或“继续”。只有用户明确丢弃时才删除恢复草稿。

## 11. 外部修改与冲突

### 11.1 clean 文档发生外部修改

在标题栏下显示全宽状态带：

```text
磁盘上的文件已更改。       [重新载入] [保留当前内容]
```

- 不自动替换当前阅读内容。
- “重新载入”重建编辑器并清空当前撤销栈。
- “保留当前内容”将当前内容视为待决版本，进入 conflict 状态，后续只能另存为或明确覆盖。

### 11.2 dirty 文档发生外部修改

- 自动保存停止。
- 标题栏显示“保存冲突”。
- 显示冲突决策对话框，不把两份内容自动合并。

对话框：

```text
文件已在其他应用中更改

磁盘版本与当前编辑内容不同。当前内容已保留在恢复草稿中。

[取消] [重新载入] [覆盖磁盘文件] [另存为…]
```

行为：

- 默认焦点为“另存为…”，这是最安全的推荐操作。
- “重新载入”在二次确认后用磁盘版本替换编辑器；确认前草稿仍保留。
- “覆盖磁盘文件”为危险样式，必须是一次明确点击，不能由 Enter 默认触发。
- “取消”回到编辑器并保持 conflict 状态。
- MVP 不提供 diff、自动合并或历史版本。

### 11.3 文件被移动或删除

状态带：

```text
原文件已被移动或删除。当前内容仍然保留。       [另存为…]
```

编辑可以继续，但自动保存停止。应用不扫描目录寻找移动后的文件。

## 12. 只读与错误状态

### 12.1 非 UTF-8

- 标题栏显示“只读”。
- 状态带文案：“此文件不是受支持的 UTF-8 编码，已以只读方式打开。”
- 正文允许滚动、查找、选择和复制，不允许编辑。
- 提供“另存为…”不是编码转换入口；MVP 不写入非 UTF-8 内容，避免误导。若无法无损解码，不允许另存转换。

### 12.2 权限只读

- 状态带说明文件不可写。
- 允许“另存为…”创建可写副本。
- 不反复请求系统权限或修改文件权限。

### 12.3 保存失败

状态带：

```text
无法保存更改，恢复草稿已保留。       [重试] [另存为…]
```

- 不循环弹出 toast。
- 新的输入继续更新恢复草稿。
- 点击状态可查看简短原因和错误代码，不显示文档内容。

### 12.4 解析降级

单个无法可靠解析的区域变为受保护源码块。只有整个文档无法建立安全分块时，才显示文档级状态带：

```text
部分内容无法安全排版，已作为源码保留。
```

不提供“忽略并格式化全部”命令。

## 13. 草稿恢复

### 13.1 已命名文件

打开文件且发现恢复草稿时：

- 草稿基线与磁盘一致：显示恢复对话框，操作为“恢复草稿”“使用磁盘版本”“另存草稿”。
- 草稿基线与磁盘不同：使用冲突语义，默认“另存草稿”。
- 在用户决策前不自动覆盖磁盘。

### 13.2 未命名草稿

- 空状态显示“未保存的草稿”和更新时间。
- 打开后作为“未命名”文档，状态“尚未保存”。
- 可继续编辑、保存或明确丢弃。
- 多个异常草稿可以来自不同窗口；每个空状态窗口最多展示最新 5 条，并与最近文件总区域保持紧凑。

### 13.3 恢复对话框

对话框不展示长篇内容预览或 diff，只显示文件名、草稿更新时间和磁盘更新时间。所有按钮使用明确动词。

## 14. 状态带与通知

状态带位于标题栏下方，是全宽页面 band，不是浮动卡片：

- 高度由内容决定，单行最小 `36px`。
- 左右 padding `16px`，正文可换行，操作保持可见。
- 中性信息使用灰色背景；警示使用低饱和黄色；错误使用低饱和红色。
- 同时最多显示一个状态带，优先级：conflict > error > missing > readonly > external change > parse notice。
- 状态带出现不覆盖正文；它将正文向下推，使用 120ms 高度过渡，并遵循 Reduce Motion。

MVP 不使用右下角 toast 堆栈。成功保存、打开和查找不产生 toast。

## 15. 对话框与菜单

### 15.1 模态对话框

- 只用于会导致内容被替换、丢弃或覆盖的决策。
- 最大宽度 `440px`，圆角 `8px`。
- 标题 `17px`，正文 `13px`，按钮使用清晰命令文本。
- 默认按钮必须是最安全、最可能继续任务的操作。
- 危险按钮使用红色文字或填充，不与默认按钮混淆。
- Escape 等同取消；存在不可逆默认操作时 Enter 不能触发危险按钮。
- 焦点锁定在对话框内，关闭后回到触发控件或编辑器。

### 15.2 菜单和 Popover

- File 菜单中的“导出”子菜单只包含“HTML…”和“PDF…”。
- HTML 和 PDF 都使用系统保存对话框选择目标文件；PDF 随后直接生成，不显示打印面板，也不在应用内增加打印设置界面。
- 链接、图片、表格控件使用与元素相关的 popover。
- popover 圆角 `6px`，阴影克制，不能套入另一张卡片。
- 点击外部和 Escape 关闭；关闭不能丢掉已经提交的编辑。
- 菜单项最小高度 `28px`，支持键盘方向键和 Enter。

### 15.3 Tooltip

- 所有纯图标按钮必须有 tooltip 和可访问名称。
- hover 约 500ms 后显示；键盘聚焦立即可见。
- tooltip 只命名操作，不写教程、功能说明或快捷键。

### 16.3 间距与圆角

基础间距序列：`4, 8, 12, 16, 24, 32, 48, 64px`。

- 图标按钮圆角 `5px`。
- 输入框、菜单、popover 圆角 `6px`。
- 模态对话框最大圆角 `8px`。
- 不使用胶囊形文本控件。
- 不使用嵌套卡片、浮动页面 section 或大面积阴影。

### 16.4 图标

- 统一使用 Lucide，stroke `1.75`。
- 常规图标 `16px`，空状态命令图标 `18px`。
- 不手绘 SVG，不混用填充风格图标。
- 熟悉操作优先图标；对话框命令使用文字按钮。

### 16.5 焦点与选择

- 键盘焦点使用 `2px` accent outline + `2px` offset。
- 文本选择颜色必须在深浅模式下清楚显示文字。
- `:focus-visible` 与鼠标点击状态区分。
- 不能仅通过阴影表达焦点。

## 17. 响应式规则

### 17.1 常规窗口 `>= 720px`

- 画布最大宽度 `880px`。
- macOS 标题区只显示文件名和必要状态；Windows/Linux 使用原生标题栏。
- 查找条固定在右上方。

### 17.2 紧凑窗口 `560-719px`

- 正文左右 margin `16px`。
- 标题栏文件名最大宽度收缩，正常状态只显示状态图标，异常使用短文案。
- 文档模式仍不显示文件操作按钮，所有文件命令保留在原生菜单和快捷键中。
- 选区工具条允许水平压缩但不能换成两行；若放不下，隐藏分隔符并保持 5 个核心操作。
- 对话框宽度 `calc(100% - 32px)`。
- 状态带操作可换到第二行，但不能覆盖正文。

### 17.3 超宽窗口

- 正文仍保持 `880px`，不随窗口无限变宽。
- 不用多栏、目录或空白装饰填充额外空间。
- 标题栏居中基于整个窗口，不基于正文列。

### 17.4 高度受限

- 标题栏固定，状态带正常占流。
- 编辑器滚动区域最少保留 `360px`。
- popover 自动翻转或限制高度；内部可滚动，但不遮挡系统标题栏。
- 560x480 下所有核心命令必须可达且无重叠。

## 19. 可访问性

### 19.1 语义

- 主编辑区域提供明确的 `aria-label="Markdown 文档"`。
- 标题栏状态使用 `role="status"`，只在状态真正变化时适度播报。
- 保存失败和冲突使用 `role="alert"`，不在每次 dirty/saving 时打断读屏。
- 工具条使用 `role="toolbar"`，按钮有名称和 pressed 状态。
- 对话框使用正确的 dialog、标题关联和描述关联。
- 最近文件为可键盘操作列表，不伪装成表格。

### 19.2 键盘

- 不使用鼠标也能完成新建、打开、编辑、查找、保存、另存为、冲突处理和关闭。
- Tab 顺序只包含当前可见控件，隐藏浮层不能残留焦点节点。
- 表格中的 Tab 行为与全局焦点移动明确区分；到达表格边界后仍可通过方向键或 Escape 离开。
- protected source 和 Frontmatter 区域支持键盘进入和退出。
- Mermaid、公式、脚注、表格源码和图表查看器都支持 Escape 返回编辑器。

### 19.3 读屏与状态

- 图标按钮名称用动作而非图标名称，例如“保存文档”而非“软盘”。
- 文件名省略时，可访问名称包含完整文件名，不默认朗读绝对路径。
- 状态变化去重，自动保存不能每 800ms 重复播报“已保存”。
- 冲突操作说明结果，例如“重新载入磁盘版本”。

### 19.4 视觉与运动

- 支持系统 Increase Contrast，不依赖半透明层区分关键控件。
- 支持 Reduce Motion；关闭状态带、popover 和 spinner 以外的非必要过渡。
- 光标、选区、焦点、查找匹配在浅色和深色下均清晰。
- 不用颜色单独表达任务完成、冲突、错误和只读。

## 20. 文案规范

### 20.1 语气

- 简短、事实化、明确下一步。
- 不拟人化，不使用营销语，不评价用户操作。
- 错误先说明发生了什么，再说明内容是否安全，最后给操作。

### 20.2 推荐文案

| 场景 | 文案 |
|---|---|
| 外部修改 | 磁盘上的文件已更改。 |
| 保存冲突 | 文件已在其他应用中更改。 |
| 保存失败 | 无法保存更改，恢复草稿已保留。 |
| 文件删除 | 原文件已被移动或删除。当前内容仍然保留。 |
| 非 UTF-8 | 此文件不是受支持的 UTF-8 编码，已以只读方式打开。 |
| 无效文件拖入 | 只能打开 .md 或 .markdown 文件。 |
| 未支持内容 | 部分内容无法安全排版，已作为源码保留。 |

### 20.3 禁止文案

- “欢迎体验强大的 Markdown 工作站”。
- “智能”“AI 驱动”“知识库”等不属于产品的表达。
- “出错了”“糟糕”这类无信息文案。
- “确定吗？”而不说明将覆盖、重新载入或丢弃什么。
- 长篇功能说明、教程和快捷键提示段落。

## 21. UI 状态矩阵

| 页面 | 文档 | 可编辑 | 顶部状态 | 主操作 |
|---|---|---:|---|---|
| 空状态 | 无 | 否 | 无 | 新建、打开、最近文件 |
| 新建空白 | untitled clean | 是 | 尚未保存 | 输入、保存 |
| 正常编辑 | file clean | 是 | 已保存 | 编辑、查找 |
| 等待保存 | file dirty | 是 | 未保存 | 继续输入、立即保存 |
| 保存中 | file saving | 是 | 正在保存 | 继续输入 |
| 冲突 | file conflict | 是 | 保存冲突 | 另存为、重载、覆盖 |
| 保存失败 | file error | 是 | 保存失败 | 重试、另存为 |
| 文件缺失 | file missing | 是 | 原文件不存在 | 另存为 |
| 编码只读 | file readonly | 否 | 只读 | 查找、复制 |
| 权限只读 | file readonly | 否 | 只读 | 查找、复制、另存为 |

这个矩阵之外的“工作区浏览”“多文档会话”“预览页”等状态不得在 MVP 中出现。

## 22. 视觉与交互验收

### 22.1 主界面

1. 首屏只有空状态或当前文档，没有营销区和侧栏。
2. 编辑状态始终只有一个文档画布。
3. 文件名和保存状态在 560px 宽度下仍可识别。
4. 880px 正文列在常规窗口内居中，超宽窗口不扩成多栏。
5. 浅色、深色和 Increase Contrast 均无文字或控件重叠。

### 22.2 编辑体验

1. PRD 指定块级语法输入后即时转换。
2. 自动保存不移动光标、不折叠选区、不改变滚动位置。
3. 浮动工具条不遮挡选区并支持键盘。
4. 链接、图片、表格、Mermaid、公式、脚注、HTML、Frontmatter 和 protected source 都能局部精确操作。
5. Mermaid 普通点击/修饰键点击、查看器缩放下载和返回编辑与 Nolia 一致。
6. 未支持语法不会消失，也不会触发脚本或远程资源。

### 22.3 文件安全体验

1. clean 文档关闭无确认、无保存动画、无文件写入。
2. dirty 未命名文档关闭时有保存/丢弃/取消。
3. 外部修改不会自动覆盖任一版本。
4. conflict、missing、readonly、error 都有明确且可键盘完成的路径。
5. 恢复草稿的存在和结果对用户清楚，不自动覆盖磁盘。

### 22.4 可访问性

1. 所有图标按钮有 tooltip 和可访问名称。
2. 全部核心流程无需鼠标即可完成。
3. 状态不只依赖颜色。
4. 焦点不会进入不可见 UI，模态关闭后返回合理位置。
5. 文本、控件、选择和焦点达到目标对比度。

## 23. 设计 QA 视口

每次可见 UI 变更至少验证：

| 视口 | 外观 | 重点 |
|---|---|---|
| `940x720` | Light | 默认布局、标题栏、正文宽度 |
| `940x720` | Dark | 对比度、代码、状态色 |
| `560x480` | Light | 最小尺寸、标题省略、对话框 |
| `560x480` | Dark | 小窗浮层、状态带、查找条 |
| `1440x900` | Light | 超宽留白、正文不扩张 |

Playwright 截图用于 WebView 视觉回归；macOS release 构建还必须人工检查 traffic lights、窗口拖动、系统菜单、文件对话框、Finder 打开和原生焦点。

## 24. 明确不设计的界面

以下界面不应出现在设计稿、组件库或隐藏入口中：

- 工作区选择器、文件树、标签页栏、面包屑。
- 大纲、字数统计、状态栏、属性面板。
- 源码/预览/分屏切换器。
- 命令面板、插件管理器、主题商店。
- AI 对话、模型设置、账号和同步。
- 导出中心、自定义导出模板、应用内打印设置、发布流程。
- 全局设置页面和快捷键编辑器。
- 移动端、Web 端和窗口内多文档布局。

若后续需求需要新增常驻区域、页面或模式，必须先通过 PRD 第 12 节的变更门槛，并同步修订产品、技术与 UI/UX 三份基线文档。
