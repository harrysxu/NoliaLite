# Nolia Lite 产品需求文档

> 版本：0.5
> 状态：当前产品基线
> 产品类型：本地、单窗口单文档 Markdown 编辑器
> 首期平台：macOS

## 1. 产品定义

Nolia Lite 是一个极简、轻量、本地优先的 Markdown 编辑器。

每个窗口一次只处理一份 Markdown 文档，并只提供一个所见即所得的编辑视图；应用可以同时打开多个独立窗口。用户看到的是排版后的文档，并直接在排版结果上编辑；应用内部和磁盘上的唯一事实来源始终是 Markdown 文本。

产品体验采用连续所见即所得、按需显现语法和上下文操作。复杂 Markdown 的渲染和编辑动作以 Nolia 的既有实现为行为基线。Nolia Lite 精简的是应用外壳和跨文档能力，不是单篇 Markdown 的编辑能力。

## 2. 核心原则

1. **单窗口单文档**：一个窗口在同一时刻只编辑一份文档，多份文档使用独立原生窗口。
2. **单模式**：只有所见即所得模式，不提供源码、预览或分屏模式。
3. **Markdown 是源文件**：不创建专有文档格式，不要求导入或迁移。
4. **界面退后**：正文始终是第一视觉主体，非必要控件不常驻。
5. **本地优先**：不登录、不联网、不上传文档、不依赖云服务。
6. **保存可信**：不静默丢失语法，不无条件覆盖外部修改，不因打开文件而改写文件。
7. **功能克制**：任何新增能力都必须直接服务于单文档 Markdown 编辑，否则默认不做。

## 3. 目标用户与场景

### 3.1 目标用户

- 需要快速查看和修改 README、说明文档、笔记或草稿的个人用户。
- 喜欢 Markdown 文件的可移植性，但不希望长期面对源码和预览分栏的用户。
- 认为知识库、项目管理、AI 和插件系统对单次写作过重的用户。

### 3.2 核心场景

- 从 Finder 双击一份 `.md` 文件并立即阅读或修改。
- 打开应用，新建一份 Markdown 文档并保存到本地。
- 同时选择或拖入多份 Markdown 文件，每份文件在独立窗口中阅读或编辑。
- 使用 Markdown 输入习惯写作，同时看到即时排版结果。

## 4. 核心交互模型

### 4.1 多窗口、单窗口单文档

- 一个窗口只显示一个编辑画布。
- 不提供标签页、文档树或多栏布局。
- 空窗口打开文件时复用当前窗口；已有文档时，新文件在独立原生窗口中打开。
- 系统文件选择、Finder 和拖放均可一次打开多份 Markdown 文件。
- 每个窗口独立保存、监听外部修改和执行关闭保护；退出应用时逐个确认未保存窗口。

### 4.2 所见即所得

- Markdown 内容在同一个编辑区域内即时呈现为标题、列表、引用、链接、图片等排版结果。
- 用户输入块级 Markdown 语法并按空格或回车后，当前块应立即转换为对应排版元素。
- 光标进入标题或行内格式时，只显示当前语法所需的轻量 Markdown 标记；正文仍在同一画布连续编辑。
- `Command/Ctrl+/` 在所见即所得画布与全文源码之间切换；不提供分屏预览，也不维护第二份文档状态。
- 编辑后的最终结果直接序列化为 Markdown 并保存，不保存 HTML。

### 4.3 界面结构

- macOS 顶部只保留窗口拖动区、当前文件名和必要的保存状态；Windows/Linux 直接使用系统原生标题栏。
- 正文使用居中的单列编辑画布，最大宽度 `880px`，在默认窗口中尽量占满可用区域。
- 格式操作优先使用 Markdown 输入规则、键盘快捷键和文本选中后的浮动工具条。
- 新建、打开、保存、另存为和导出由系统菜单、快捷键承担；无文档时，历史面板提供紧凑的新建和打开图标入口。
- 有标题且窗口宽度足够时，文档模式显示轻量左侧大纲；不提供文件树、属性栏、底部状态栏或功能面板。
- 未打开文档时，左侧显示恢复草稿和最多 5 个最近文件，支持单条移除和一键清空最近记录。

## 5. MVP 功能范围

| 编号 | 能力 | MVP 要求 |
|---|---|---|
| F-01 | 新建文档 | 创建一份未命名的空白 Markdown 文档 |
| F-02 | 打开文档 | 支持 `.md` 和 `.markdown`，支持系统文件多选、Finder 打开方式、拖放和独立窗口 |
| F-03 | 保存 | `Command+S` 立即保存；已有路径的文档可在停止输入后自动保存 |
| F-04 | 另存为 | 支持将当前内容保存到新的 Markdown 文件 |
| F-05 | 恢复草稿 | 保存失败或应用异常退出后，可恢复未落盘内容 |
| F-06 | 撤销与重做 | 支持标准系统快捷键，撤销栈只属于当前文档 |
| F-07 | 查找 | 支持当前文档内查找，不做跨文件搜索和替换 |
| F-08 | 最近文件 | 本地保存最多 5 条记录，不扫描目录 |
| F-09 | 外部修改 | 检测磁盘文件变化，禁止无提示覆盖，提供重新载入或保留当前内容 |
| F-10 | 窗口状态 | 每个窗口的文件名和未保存状态清晰可见；关闭窗口或退出应用前保证内容已保存或已进入恢复草稿 |
| F-11 | Mermaid 图表 | 流程图、时序图等可渲染、局部编辑、查看、缩放和导出 |
| F-12 | 复杂块编辑 | 表格、代码、图片、公式、脚注、HTML 等采用聚焦时出现的上下文操作 |
| F-13 | Markdown 保真 | 复杂块复制、粘贴、编辑和保存后仍以 Markdown 源码为事实来源 |
| F-14 | 文档导出 | 从文件菜单导出独立 HTML 或直接生成 PDF 文件；不显示打印对话框，不改写源 Markdown |
| F-15 | 文档大纲 | 宽窗口按 H1-H6 显示当前文档大纲，点击标题跳转且不修改文档 |

## 6. Markdown 支持边界

### 6.1 MVP 必须支持

- 普通段落与软换行。
- 一级至六级标题。
- 粗体、斜体、删除线。
- 行内代码与围栏代码块。
- 有序列表、无序列表和任务列表。
- 引用块与分隔线。
- 行内链接。
- 本地图片路径，包括相对路径、父目录路径和绝对路径；远程图片不主动加载。
- GFM 表格的显示、插入、结构调整、对齐和局部源码编辑。
- Mermaid 及 Nolia 已支持的 Mermaid 围栏别名，包括流程图和时序图。
- KaTeX 行内公式与块公式。
- 脚注引用与脚注定义。
- 代码语言标识与语法高亮。
- 图片和安全 HTML 的局部 Markdown 源码编辑。
- 已渲染链接普通点击直接导航；`Command/Ctrl+Click` 在新窗口打开本地 Markdown 文档，支持相对、父目录、绝对和无扩展名路径；`Command/Ctrl+K` 编辑链接。
- 选择、拖入或粘贴本地图片时，复制到当前文档旁的 `assets/` 目录并写入相对路径；未保存文档必须先保存。
- `Command/Ctrl+/` 提供单一全文源码模式；切换时使用当前 Markdown 字符串重建画布。
- YAML Frontmatter 的原样保留。

### 6.2 保真规则

- 仅打开、阅读并关闭文档时，文件内容和时间戳不得变化。
- 保存时保留原文件的 UTF-8 BOM 状态与 LF/CRLF 换行风格。
- Frontmatter 未被用户编辑时必须逐字节保留。
- 链接和图片的原始路径字符串不得被自动改写或规范化。
- 无法安全渲染的 Markdown 或 HTML 必须作为受保护的源码块保留；不得静默删除或执行脚本。
- 编辑器可以规范化用户实际修改过的块，但不应格式化整篇未修改文档。
- 保存采用冲突检查和安全替换，不能无条件覆盖其他应用刚写入的版本。

### 6.3 编辑能力与应用能力的边界

Nolia Lite 的“Lite”只约束应用外壳。单篇 Markdown 文档采用连续所见即所得、按光标显现语法、独立全文源码模式、上下文控件和原生菜单命令；磁盘 Markdown 仍是唯一事实来源。

以下能力仍明确不支持：

- PlantUML 等需要独立运行时或网络服务的非 Mermaid 图表引擎。
- 跨文档引用文献、自动目录维护和全库脚注索引。
- Wiki Link、反向链接、标签和双向链接。
- 自定义 Markdown 插件或用户脚本。
- 对远程图片的自动下载和本地化。
- 可视化 Frontmatter 表单编辑器。

## 7. 文件与保存策略

### 7.1 文件格式

- 磁盘格式只允许 Markdown 文本。
- MVP 只写入 UTF-8；非 UTF-8 文件以只读方式打开，并提示编码不受支持。
- 新文档默认使用 UTF-8、无 BOM、LF 换行。

### 7.2 自动保存

- 已有文件路径且可写时，用户停止输入约 `800ms` 后自动保存。
- `Command+S` 绕过等待并立即保存。
- 新建且尚未选择路径的文档不自动弹出保存窗口，只在用户主动保存或关闭时询问路径。
- 自动保存失败时保留内存内容和恢复草稿，并停止重复覆盖尝试。

### 7.3 外部冲突

- 每次保存前比较打开时或上次保存后的文件指纹。
- 指纹不一致时不写入磁盘。
- 用户可以选择重新载入磁盘版本、保留当前版本并另存为，或明确确认覆盖。
- 文件被移动或删除时，当前内容继续保留，并允许另存为新文件。

## 9. 非功能要求

### 9.1 轻量性目标

- 首次可交互时间目标：参考设备冷启动不超过 `1.5s`。
- macOS 安装包目标：不超过 `25MB`，不随应用打包独立 Chromium。
- 空闲内存目标：不超过 `120MB`。
- 打开 2MB 或 10,000 行以内的常规 Markdown 文档时，输入和滚动保持流畅。

### 9.2 隐私与安全

- 应用运行不需要账户。
- 默认不发起任何网络请求。
- 不收集遥测、文档内容、文件路径或使用记录。
- 原始 HTML 不执行脚本、事件处理器或嵌入内容。
- 最近文件和恢复草稿只保存在本机应用数据目录。

### 9.3 可访问性

- 所有图标按钮具有可访问名称和悬停提示。
- 键盘可以完成全部核心文件和编辑操作。
- 正文、选择状态、焦点状态在浅色和深色系统外观下保持足够对比度。
- 界面在最小 `560x480` 窗口内不得出现控件遮挡。

## 10. 明确的产品非目标

以下能力不进入 Nolia Lite；未来若需要，应由 Nolia 工作站或其他独立产品承担：

- 工作区、文件夹树和知识库管理。
- 多标签页和跨启动窗口会话恢复。
- 全文检索、跨文档搜索、最近编辑聚合。
- 文档属性、历史版本、关系图和反向链接。
- AI 写作、问答、向量索引或模型设置。
- 插件系统、扩展市场和命令面板。
- 云同步、账户、团队协作、评论和权限。
- Word、RTF、EPUB 等需要办公套件或独立转换运行时的导入导出。
- Markdown、HTML、PDF 的导入，以及批量导出、导出中心、模板和复杂打印设置。
- 主题商店、复杂排版设置和自定义 CSS。
- 移动端、Web 端和浏览器扩展。

## 11. MVP 验收标准

1. 双击一份 `.md` 文件后，应用直接进入该文档的渲染编辑画布，没有工作区选择步骤。
2. 每个文档窗口只存在一份文档，不出现标签页、文件树、属性侧栏或预览分栏；有标题的文档可显示当前文档大纲，多个 Markdown 文件可在独立窗口中同时打开。
3. 输入 `# `、`> `、`- `、`1. `、三个反引号等常用语法后，当前块即时形成对应排版。
4. 编辑标题、段落、列表、引用、代码、链接、图片、表格、公式、脚注、HTML 和 Mermaid 后，重新打开文件所得内容与保存前一致。
5. 未修改文档直接关闭时，文件哈希和修改时间保持不变。
6. 文件包含 Frontmatter 或不支持语法时，保存后这些内容没有丢失。
7. 其他应用修改同一文件后，Nolia Lite 不会静默覆盖磁盘版本。
8. 应用异常退出后，重新打开同一文件可以恢复尚未成功保存的内容。
9. 断网环境下所有 MVP 能力正常工作，运行过程中不产生网络请求。
10. 应用达到轻量性、响应性和窗口最小尺寸目标。
11. Mermaid 普通点击进入局部源码，`Command/Ctrl+Click` 打开查看器；查看器支持缩放、重置、PNG 下载和返回编辑。
12. 表格支持插入、行列增删、尺寸调整、对齐、表头切换、右键菜单和局部 Markdown 源码编辑。
13. 已有链接普通点击直接打开目标，`Command/Ctrl+Click` 在新窗口打开相对 Markdown 文档，`Command/Ctrl+K` 可编辑链接。
14. 文件菜单提供 HTML 和 PDF 导出；HTML 为可独立打开的 UTF-8 文件，PDF 选择目标路径后由系统 WebView 直接生成，过程不显示打印对话框，源 Markdown 的哈希和 mtime 不变化。
15. 系统文件多选、多文件拖放和 Finder 连续打开会为每份文件建立独立窗口；重复打开同一路径时聚焦已有窗口，每个窗口的文件监听和关闭保护互不干扰。

## 12. 需求变更门槛

新增需求必须同时回答以下问题：

1. 它是否直接改善单份 Markdown 文档的打开、阅读或编辑？
2. 它是否可以在不增加常驻界面区域的情况下完成？
3. 它是否会引入账户、网络、数据库、索引、插件或跨文档状态？
4. 它是否影响 Markdown 保真、启动速度、安装体积或内存目标？

只要第 1 项答案为“否”，或第 3 项答案为“是”，该需求默认不进入 Nolia Lite。
